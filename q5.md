
## Question 5

1. Create a **ServiceAccount** in namespace `monitoring`
   → **automountServiceAccountToken: false**

2. In a **Deployment**, mount this serviceAccount’s token **as a projected volume**
   → token must be **readOnly**
   → must use `serviceAccountToken` type projection
   → must specify `audience` + `path` + `expirationSeconds`
---

### Solution:

**Reference:**
- https://kubernetes.io/docs/concepts/storage/projected-volumes/#serviceaccounttoken

> **Note (corrected):** `mountPath` is the **directory** the volume is mounted at; `path` is the
> **file name** created inside it — not a folder. With `mountPath: /var/run/secrets/tokens` and
> `path: token`, the token lands at **`/var/run/secrets/tokens/token`**. Verified:
>
> ```
> $ kubectl exec <pod> -- ls -la /var/run/secrets/tokens/
> lrwxrwxrwx 1 root root 12 Oct  4 09:44 token -> ..data/token
> ```

## **Step 1 — Create the ServiceAccount**

```bash
kubectl create namespace monitoring
kubectl create serviceaccount monitor-sa -n monitoring
```

Now edit it:

```bash
kubectl edit sa monitor-sa -n monitoring
```

Add:

```yaml
automountServiceAccountToken: false
```
## **Step 2 — Modify Deployment to use projected token**

Open file or edit:

```bash
kubectl edit deployment mydeploy -n monitoring
```

Add under `.spec.template.spec`:

### volumes:

```yaml
volumes:
- name: token-vol
  projected:
    sources:
    - serviceAccountToken:
        path: token
        audience: api
        expirationSeconds: 3600
```

### container volumeMounts:

```yaml
containers:
- name: app
  image: myimg
  volumeMounts:
  - name: token-vol
    mountPath: /var/run/secrets/tokens
    readOnly: true
```

### serviceAccountName:

```yaml
serviceAccountName: monitor-sa
```

# **FULL EXPECTED ANSWER (Copy/Paste Ready)**

### **ServiceAccount**

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: monitor-sa
  namespace: monitoring
automountServiceAccountToken: false
```

### **Deployment**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: secure-app
  namespace: monitoring
spec:
  replicas: 1
  template:
    spec:
      serviceAccountName: monitor-sa

      volumes:
      - name: token-vol
        projected:
          sources:
          - serviceAccountToken:
              path: token            # FILE name inside mountPath
              audience: api
              expirationSeconds: 3600

      containers:
      - name: app
        image: nginx
        volumeMounts:
        - name: token-vol
          mountPath: /var/run/secrets/tokens  # PARENT DIR
          readOnly: true
```

### ✅ Validated on a live cluster — this answer is correct as written

```
$ kubectl -n monitoring get sa monitor-sa -o jsonpath='{.automountServiceAccountToken}'
false

$ kubectl -n monitoring exec <pod> -- ls -la /var/run/secrets/tokens/
token -> ..data/token

# the default SA token is genuinely gone (automountServiceAccountToken: false)
$ kubectl -n monitoring exec <pod> -- ls /var/run/secrets/kubernetes.io/serviceaccount/
ls: cannot access '...': No such file or directory

# decoded JWT payload proves audience + expirationSeconds took effect
{"aud":["api"],"exp":1791110694,"iat":1791107094,
 "iss":"https://kubernetes.default.svc.cluster.local",
 "sub":"system:serviceaccount:monitoring:monitor-sa"}
```

`exp - iat = 1791110694 - 1791107094 = 3600` → `expirationSeconds: 3600` confirmed, and `aud` is `["api"]`.

### 🔍 How to self-check in the exam

```bash
kubectl -n monitoring exec <pod> -- cat /var/run/secrets/tokens/token \
  | cut -d. -f2 | base64 -d; echo
```

Three things graders look for, all easy to miss:

1. `automountServiceAccountToken: false` goes on the **ServiceAccount** (top level, *not* under `spec`).
2. `readOnly: true` goes on the **volumeMount**, not on the projection.
3. `serviceAccountName` must be set on the **Pod template**, or the projected token belongs to `default`.
