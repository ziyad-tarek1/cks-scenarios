
## Question 9

1. **Enable audit logging** in the kube-apiserver.
2. Add `--audit-policy-file=/etc/kubernetes/audit/audit.yaml`
3. Configure log rotation:

   * `--audit-log-maxage=<given>`
   * `--audit-log-maxbackup=<given>`
   * `--audit-log-maxsize=<given>` (usually also needed)
4. Create an **audit policy** with:

   * **All namespaces:** request metadata
   * **`web-apps` namespace:** deployments → audit **metadata level**
   * **All namespaces:** delete on ConfigMaps & Secrets → **RequestResponse body**
   * Everything else → **Metadata**

---

### Solution:

**Reference:**
- https://kubernetes.io/docs/tasks/debug/debug-cluster/audit/


# ✅ **Step 1 – Edit kube-apiserver manifest**

File:

```
/etc/kubernetes/manifests/kube-apiserver.yaml
```

#### 1a. Create both directories on the node **first**

```bash
sudo mkdir -p /etc/kubernetes/audit      # will hold audit.yaml
sudo mkdir -p /var/log/kubernetes        # will hold audit.log
```

#### 1b. Add the flags under `command:`

```yaml
    - --audit-policy-file=/etc/kubernetes/audit/audit.yaml
    - --audit-log-path=/var/log/kubernetes/audit.log
    - --audit-log-maxage=5
    - --audit-log-maxbackup=10
    - --audit-log-maxsize=100
```

#### 1c. ⛔ Add the hostPath mounts — **the flags alone are not enough**

This is the step the solution used to be missing, and it is the single thing most likely to cost you the
task. kube-apiserver is a **static pod**: it only sees paths that are explicitly mounted into it. kubeadm
mounts `/etc/kubernetes/pki` — **not** `/etc/kubernetes` — so your policy file is invisible to it.

Verified on a live cluster: adding only the flags above puts the API server into a crash loop and
`kubectl` dies with `Unable to connect to the server: EOF`. The reason is only visible on the node:

```
$ crictl logs $(crictl ps -a --name kube-apiserver -q | head -1)
E1004 09:51:07.690782  1 run.go:72] "command failed"
  err="loading audit policy file: failed to read file path \"/etc/kubernetes/audit/audit.yaml\":
       open /etc/kubernetes/audit/audit.yaml: no such file or directory"
```

Add **two** `volumeMounts` and the matching **two** `volumes` in the same manifest:

```yaml
spec:
  containers:
  - name: kube-apiserver
    # ...
    volumeMounts:
    - mountPath: /etc/kubernetes/audit
      name: audit-policy
      readOnly: true
    - mountPath: /var/log/kubernetes
      name: audit-log
      readOnly: false          # the API server must WRITE here
    # ... existing mounts (k8s-certs, ca-certs, ...) stay as they are
  volumes:
  - hostPath:
      path: /etc/kubernetes/audit
      type: DirectoryOrCreate
    name: audit-policy
  - hostPath:
      path: /var/log/kubernetes
      type: DirectoryOrCreate
    name: audit-log
  # ... existing volumes stay as they are
```

> Mind the indentation: `volumeMounts` is nested under the container, `volumes` under `spec`.
> And `readOnly: false` on the log mount — a read-only log directory fails just as hard.

# ✅ **Step 2 – Create audit policy**

File:

```
/etc/kubernetes/audit/audit.yaml
```

Content:

```yaml
apiVersion: audit.k8s.io/v1
kind: Policy

# Default level
rules:

  # 1️⃣ Log delete operations of ConfigMaps & Secrets with RequestResponse body
  - level: RequestResponse
    verbs: ["delete"]
    resources:
    - group: ""
      resources: ["configmaps", "secrets"]

  # 2️⃣ Capture Deployments interactions in web-apps namespace (metadata)
  - level: Metadata
    resources:
    - group: "apps"
      resources: ["deployments"]
    namespaces: ["web-apps"]

  # 3️⃣ Log ALL namespace interactions (request only)
  - level: Request
    resources:
    - group: ""
      resources: ["namespaces"]

  # 4️⃣ Everything else at Metadata level
  - level: Metadata
```

> ⚠️ **Rules are first-match-wins, so order matters.** The `RequestResponse` rule for configmap/secret
> deletes must come **before** the bare `- level: Metadata` catch-all, or the catch-all swallows
> everything. Keep the catch-all last.
>
> ⚠️ **Requirement 1 is ambiguous — read your screen carefully.** "All namespaces: request metadata" can
> mean either *"log the `namespaces` resource at `Request` level"* (rule 3 above) or *"log everything at
> `Metadata` level"* (rule 4). The policy above covers both readings, which is the safe play.
>
> 💡 Commonly also expected: `omitStages: ["RequestReceived"]` at the top level, to halve the log volume
> by dropping the duplicate pre-execution entry for every event.

# ✅ Step 3 — Verify (the policy above was validated on a live cluster)

```bash
# 1. The API server came back up
kubectl get --raw /healthz          # ok

# 2. The log file exists and is growing
sudo ls -la /var/log/kubernetes/
# -rw------- 1 root root 461014 Oct  4 09:51 audit.log
```

Then generate traffic and confirm each rule produced the level it promised:

```bash
kubectl create ns web-apps
kubectl -n web-apps create deployment audit-test --image=nginx
kubectl -n default create configmap audit-cm --from-literal=k=v && \
  kubectl -n default delete configmap audit-cm

L=/var/log/kubernetes/audit.log
grep '"verb":"delete"' $L | grep -E '"resource":"(configmaps|secrets)"' | grep -o '"level":"[^"]*"' | sort -u
grep '"resource":"deployments"' $L | grep '"namespace":"web-apps"'      | grep -o '"level":"[^"]*"' | sort -u
grep '"resource":"namespaces"'  $L                                      | grep -o '"level":"[^"]*"' | sort -u
grep '"resource":"pods"'        $L                                      | grep -o '"level":"[^"]*"' | sort -u
```

Measured results — each rule fired at the right level:

| Rule | Expected | Observed |
|---|---|---|
| delete configmaps/secrets | `RequestResponse` | ✅ `RequestResponse` (and `responseObject` present in the body) |
| deployments in `web-apps` | `Metadata` | ✅ `Metadata` |
| `namespaces` resource | `Request` | ✅ `Request` |
| everything else (e.g. pods) | `Metadata` | ✅ `Metadata` |

### 🔍 If the API server doesn't come back

`kubectl` will not help you — the API server *is* down. On the control-plane node:

```bash
sudo crictl ps -a --name kube-apiserver
sudo crictl logs $(sudo crictl ps -a --name kube-apiserver -q | head -1) | tail -20
```

Back up the manifest **before** you edit it (`cp /etc/kubernetes/manifests/kube-apiserver.yaml /tmp/`)
so you can always restore a working file.
