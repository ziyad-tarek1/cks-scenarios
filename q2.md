## Question 2

> Configure the cluster to disable **anonymous-auth** in the **kube-apiserver** and 

delete the clusterrole system:user using the kubeconfig located at /root/candiented/kubeconfig
Note: after disable the **anonymous-auth** your kubectl commands will not work

---

### Solution:

#### 🧱 Step 1 — Edit API Server Static Pod

```bash
sudo vim /etc/kubernetes/manifests/kube-apiserver.yaml
```

Add or modify the following flags under `command:`:

```yaml
- --anonymous-auth=false
```

> 💡 Note: Make sure `--authorization-mode` is not duplicated — merge into one line if needed.

Save and exit — the static pod will restart automatically.

---

#### 🧱 Step 2 — Verify Changes (Before kubectl stops working)

Run:

```bash
ps -ef | grep kube-apiserver
```

Ensure you see:

```
--anonymous-auth=false
```

Check that the API server pod is running again:

```bash
kubectl get pods -n kube-system
```

> ⚠️ **Important:** After this change, kubectl commands will no longer work without proper authentication. You'll need to use the kubeconfig file for all subsequent operations.

---

#### 🧱 Step 3 — Test Anonymous Access Blocked

Try an unauthenticated curl:

```bash
curl -k https://localhost:6443/version
```

You should see:

```
Unauthorized
```

That means anonymous-auth is disabled.

---

#### 🧱 Step 4 — Delete ClusterRole using kubeconfig

Since kubectl commands no longer work after disabling anonymous-auth, use the provided kubeconfig file:

```bash
# Verify the kubeconfig file exists
ls -la /root/candiented/kubeconfig

# Use kubectl with the kubeconfig file to check if clusterrole exists
sudo kubectl --kubeconfig=/root/candiented/kubeconfig get clusterrole system:user

# Delete the clusterrole
sudo kubectl --kubeconfig=/root/candiented/kubeconfig delete clusterrole system:user

# Verify it's deleted
sudo kubectl --kubeconfig=/root/candiented/kubeconfig get clusterrole system:user
```

Expected output after deletion:
```
Error from server (NotFound): clusterroles.rbac.authorization.k8s.io "system:user" not found
```

---

### 🧠 Summary

* API server now denies any unauthenticated access.
* After disabling anonymous-auth, kubectl commands require proper authentication.
* Use `sudo` with the provided kubeconfig file (`/root/candiented/kubeconfig`) for all kubectl operations after the change.
* The `system:user` clusterrole has been deleted.
