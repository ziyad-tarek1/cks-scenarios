
## Question 10

1. Remove user **developer** from **docker** group
2. Disable **TCP** access to Docker daemon
3. Make Docker listen **only** on the Unix socket:

   ```
   /var/run/docker.sock
   ```
---

### Solution:
# ✅ **Step 1 — Remove user developer from docker group**

```bash
sudo gpasswd -d developer docker
```

Or:

```bash
sudo deluser developer docker
```

Confirm:

```bash
id developer
```

You should NOT see `docker` group.

---

# ✅ **Step 2 — Deny TCP traffic to Docker daemon**

Docker listens on TCP only if you explicitly enabled it in:

```
/etc/docker/daemon.json
```

Edit it to **remove any TCP host**:

### ❌ If you have:

```json
{
  "hosts": [
    "tcp://0.0.0.0:2375",
    "unix:///var/run/docker.sock"
  ]
}
```

### ✅ Replace with:

```json
{
  "hosts": [
    "unix:///var/run/docker.sock"
  ]
}
```

---

> ### ⛔ Do **not** also put `-H` in the systemd unit — verified, Docker will refuse to start
>
> If `hosts` is set in `daemon.json` **and** `-H` is passed on the `dockerd` command line, the daemon
> exits immediately. Reproduced with `dockerd --validate`:
>
> ```
> unable to configure the Docker daemon with file /etc/docker/daemon.json:
>   the following directives are specified both as a flag and in the configuration file:
>   hosts: (from flag: [unix:///var/run/docker.sock], from file: [unix:///var/run/docker.sock])
> ```
>
> Note it fails **even when both values are identical** — it is the duplication itself that is rejected.
> So pick exactly **one** of Step 2 or Step 3, not both:
>
> * **Option A** — `hosts` in `daemon.json`, and `ExecStart=/usr/bin/dockerd` with **no** `-H` at all.
> * **Option B** — `-H unix:///var/run/docker.sock` in the unit, and **no** `hosts` key in `daemon.json`.
>
> Option B is the safer exam answer: it is the one that matches how the host was already configured if a
> TCP `-H` was present in the unit file.

---

# ✅ **Step 3 — Enforce Unix Socket Only (alternative to Step 2 — don't do both)**

Ensure Docker is **not listening on TCP**.

Check service file:

```
/lib/systemd/system/docker.service
```

Look for:

```
ExecStart=/usr/bin/dockerd
```

If you see any `-H tcp://...`, delete it.

Example:

### ❌ If you have:

```
ExecStart=/usr/bin/dockerd -H tcp://0.0.0.0:2375 -H unix:///var/run/docker.sock
```

### ✅ Replace with:

```
ExecStart=/usr/bin/dockerd -H unix:///var/run/docker.sock
```

Then reload & restart:

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```

---

# 🔐 **Step 4 — (Optional but expected in CKS) Block port 2375 using firewall**

If TCP was previously exposed, block it:

### UFW:

```bash
sudo ufw deny 2375/tcp
```

### IPTables:

```bash
sudo iptables -A INPUT -p tcp --dport 2375 -j DROP
```

# 🔍 Verification

### Check Docker isn't listening on TCP:

```bash
sudo ss -ltnp | grep dockerd
```

**Expected output: nothing at all.** Empty output = pass.

> ⛔ **Corrected.** This file used to claim you'd see `unix /var/run/docker.sock` here. That is
> impossible: `-t` restricts `ss` to **TCP**, so a unix socket can never appear in `ss -ltnp`. Verified on
> a live node — `ss -ltnp | grep -c unix` returns `0`, always.

To positively confirm the **unix** socket is listening, you need `-x`:

```bash
sudo ss -lxp | grep docker.sock
# u_str LISTEN 0 4096 /var/run/docker.sock ... users:(("dockerd",pid=...))
```

Full verification set:

```bash
sudo ss -ltnp | grep dockerd          # expect: no output  (no TCP listener)
sudo ss -lxp  | grep docker.sock      # expect: a line     (unix socket present)
sudo systemctl is-active docker       # expect: active     (it actually restarted)
docker info >/dev/null && echo OK     # expect: OK         (client still works)
id developer                          # expect: no 'docker' group
```

That third check matters: a bad `daemon.json` leaves Docker **dead**, and `ss` showing no TCP listener
would then be a false pass.
