## Question 8

A namespace named **`confidential`** has **Pod Security Admission (restricted)** applied.

Meaning:

🔒 Only **restricted** security settings are allowed in this namespace.
❌ Default pods will **NOT start** unless they meet restricted rules.

**Your task:**

👉 Modify the Pod/Deployment YAML so it **complies with the restricted PSA**.
---

### Solution:

> **Note:** This solution applies to Pods with two containers.

## **Step 1 — Inspect namespace**

```bash
kubectl get ns confidential --show-labels
```

You will see something like:

```
pod-security.kubernetes.io/enforce=restricted
```

---

## **Step 2 — Try to create a pod (it fails)**

You might see errors like:

```
pod is forbidden: violates PodSecurity "restricted"
```

This is expected.

---

## **Step 3 — Patch your Pod/Deployment to satisfy "restricted"**

The **four** settings `restricted` actually requires:

```yaml
securityContext:
  runAsNonRoot: true
  allowPrivilegeEscalation: false
  seccompProfile:
    type: RuntimeDefault        # <-- REQUIRED. Omitting it is the #1 failure here.
  capabilities:
    drop:
    - ALL
```

Plus `runAsUser: <UID>` if the task names one (not required by `restricted` itself — any non-root UID
passes, including one baked into the image).

`runAsNonRoot` and `seccompProfile` may be set at **pod** level and inherited; `allowPrivilegeEscalation`
and `capabilities` must be set per **container**.

---

### ⛔ The exact mistake this file used to contain — reproduced on a live cluster

The old answer listed `readOnlyRootFilesystem` but **not** `seccompProfile`. Applied to a namespace with
`pod-security.kubernetes.io/enforce=restricted`, every Pod is rejected:

```
$ kubectl apply -f deploy.yaml
Warning: would violate PodSecurity "restricted:latest": seccompProfile
  (pod or container "app" must set securityContext.seccompProfile.type to "RuntimeDefault" or "Localhost")
deployment.apps/secure-app created        # <- the Deployment is created...

$ kubectl -n confidential describe rs -l app=secure-app
Warning  FailedCreate  replicaset-controller  Error creating: pods "secure-app-..." is forbidden:
  violates PodSecurity "restricted:latest": seccompProfile (pod or container "app" must set
  securityContext.seccompProfile.type to "RuntimeDefault" or "Localhost")
```

Note the trap: **the Deployment applies cleanly** and only prints a `Warning`. The rejection happens when
the ReplicaSet tries to create Pods. `kubectl get deploy` shows `0/1` and nothing else looks wrong — so
always check `kubectl get pods`, and if there are none, `kubectl describe rs`.

### ⚠️ And `readOnlyRootFilesystem` is **not** part of `restricted`

Also verified — this Pod was admitted with no `readOnlyRootFilesystem` at all:

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  allowPrivilegeEscalation: false
  seccompProfile: {type: RuntimeDefault}
  capabilities: {drop: ["ALL"]}
```

Keep it if the task asks for it (it's good practice and `q3`/`q4` do ask). Don't rely on it to satisfy
`restricted`, and don't let it distract you from `seccompProfile`.

---

# 📌 **FINAL YAML FIX (What the CKS grader expects)**

**Example Deployment inside `confidential` namespace:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: secure-app
  namespace: confidential
spec:
  replicas: 1
  selector:
    matchLabels:
      app: secure-app
  template:
    metadata:
      labels:
        app: secure-app
    spec:
      securityContext:                 # pod level: inherited by all containers
        runAsNonRoot: true
        runAsUser: 1000
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: app
        image: nginx
        securityContext:               # container level: these two must be here
          allowPrivilegeEscalation: false
          capabilities:
            drop:
            - ALL
```

**With two containers, repeat the container-level block on each one** (the pod-level block is shared):

```yaml
      containers:
      - name: app1
        image: myimg1:v1
        securityContext:
          allowPrivilegeEscalation: false
          capabilities: {drop: ["ALL"]}
      - name: app2
        image: myimg2:v1
        securityContext:
          allowPrivilegeEscalation: false
          capabilities: {drop: ["ALL"]}
```

### ✅ Verified admitted

Applied to `confidential` with `enforce=restricted` — no PodSecurity warning, Pod created.

> ⚠️ Admitted ≠ Running. Stock `nginx` as UID 1000 crashes with
> `mkdir() "/var/cache/nginx/client_temp" failed (13: Permission denied)`. PSA only gates **admission**,
> so this still passes the task; see the gotcha in `q3.md` if you need it actually Running.

### 🔍 Fast self-check before moving on

```bash
# Dry-run against the real admission controller — no objects created:
kubectl -n confidential apply -f deploy.yaml --dry-run=server

# Or ask PSA directly by labelling a scratch namespace with warn/audit:
kubectl label ns scratch pod-security.kubernetes.io/warn=restricted
```

If `--dry-run=server` prints no `violate PodSecurity` warning, you're done.
