
## Question 13

1. Enable `ImagePolicyWebhook` in kube-apiserver
2. Add the full path of `kube.conf` in `/etc/kubernetes/imagepolicy/imagepolicyfile.yaml`
3. Change default allow = **false**
4. In `kube.conf`, set the `server:` URL (given in exam)
5. Test by applying the ReplicationController YAML

---

kubeadm clusters store the kube-apiserver flags in:

```
/etc/kubernetes/manifests/kube-apiserver.yaml
```

You edit this file → kubelet automatically restarts the API server.

---

# ✅ Step 1 — Create directory for ImagePolicyWebhook

```bash
sudo mkdir -p /etc/kubernetes/imagepolicy
```

---

# ✅ Step 2 — Create the image policy config file

File path:

```
/etc/kubernetes/imagepolicy/imagepolicyfile.yaml
```

Content:

```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: AdmissionConfiguration
plugins:
- name: ImagePolicyWebhook
  configuration:
    imagePolicy:
      kubeConfigFile: /etc/kubernetes/imagepolicy/kube.conf
      allowTTL: 50
      denyTTL: 50
      retryBackoff: 500
      defaultAllow: false        # <-- requirement 3
```

> ### ⛔ This file previously had the format wrong — verified fatal
>
> The old content used `kind: ImagePolicyWebhook` with `apiVersion: imagepolicy.k8s.io/v1alpha1` as the
> top-level object. `--admission-control-config-file` does **not** accept that; the API server refuses to
> start:
>
> ```
> E1004 09:53:05.053292  1 run.go:72] "command failed"
>   err="failed to apply admission: failed to read plugin config:
>        no kind \"ImagePolicyWebhook\" is registered for version \"imagepolicy.k8s.io/v1alpha1\"
>        in scheme \"pkg/server/options/admission.go:51\""
> ```
>
> The file must be an **`AdmissionConfiguration`** (`apiserver.config.k8s.io/v1`) whose `plugins:` list
> names `ImagePolicyWebhook`, with the old fields nested under `configuration.imagePolicy`. The version
> above was confirmed to boot cleanly (`kubectl get --raw /healthz` → `ok`).
>
> **Equivalent alternative** — point at a second file instead of inlining, using `path:` (relative paths
> resolve next to the admission config file):
>
> ```yaml
> apiVersion: apiserver.config.k8s.io/v1
> kind: AdmissionConfiguration
> plugins:
> - name: ImagePolicyWebhook
>   path: imagepolicy.yaml
> ```
>
> ...where `imagepolicy.yaml` contains just the `imagePolicy:` block. Inlining is fewer moving parts.

# ✅ Step 3 — Create the kube.conf for the webhook client

Location:

```
/etc/kubernetes/imagepolicy/kube.conf
```

Content (example URL from exam):

```yaml
apiVersion: v1
kind: Config
clusters:
- cluster:
    server: https://image-webhook.example.com:443
    insecure-skip-tls-verify: true
  name: image-policy-cluster
contexts:
- context:
    cluster: image-policy-cluster
    user: image-bot
  name: image-policy-context
current-context: image-policy-context
users:
- name: image-bot
  user:
    token: dummy-token
```

The important part is:

```
server: <URL from question>
```

# ✅ Step 4 — Enable ImagePolicyWebhook in kube-api server

Edit:

```
sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml
```

Add to command arguments:

```yaml
- --enable-admission-plugins=NodeRestriction,ImagePolicyWebhook
- --admission-control-config-file=/etc/kubernetes/imagepolicy/imagepolicyfile.yaml
```

`--enable-admission-plugins` already exists on a kubeadm cluster (usually `NodeRestriction`) — **append**
`,ImagePolicyWebhook` to that one line. Do not add a second copy of the flag.

#### ⛔ Also add the hostPath mount — the flags alone are not enough

Same trap as the audit task (`q9.md`): kube-apiserver is a static pod and kubeadm mounts only
`/etc/kubernetes/pki`, **not** `/etc/kubernetes`. Without this, both your config file and `kube.conf` are
invisible to the API server and it crash-loops.

```yaml
spec:
  containers:
  - name: kube-apiserver
    volumeMounts:
    - mountPath: /etc/kubernetes/imagepolicy
      name: imagepolicy
      readOnly: true
    # ... existing mounts stay
  volumes:
  - hostPath:
      path: /etc/kubernetes/imagepolicy
      type: DirectoryOrCreate
    name: imagepolicy
  # ... existing volumes stay
```

Save the file — **kubelet automatically restarts kube-apiserver**.

Check the API server came back:

```bash
kubectl get --raw /healthz           # expect: ok
kubectl get pods -n kube-system
```

If `kubectl` hangs with `Unable to connect to the server: EOF`, read the real error on the node:

```bash
sudo crictl logs $(sudo crictl ps -a --name kube-apiserver -q | head -1) | tail -20
```

# ✅ Step 5 — Test using the provided ReplicationController YAML

The exam will give you something like:

```yaml
kubectl apply -f test-rc.yaml
```

### ⛔ Corrected expected behaviour — the RC is **always** created

The ImagePolicyWebhook gates **Pods**, not ReplicationControllers. Verified on a live cluster with
`defaultAllow: false` and an unreachable webhook:

```
$ kubectl apply -f test-rc.yaml
replicationcontroller/test-rc created          # <-- the RC succeeds!

$ kubectl get rc test-rc
NAME      DESIRED   CURRENT   READY   AGE
test-rc   1         0         0       6s      # CURRENT stays 0

$ kubectl get po -l app=test-rc
No resources found in default namespace.

$ kubectl describe rc test-rc
Warning  FailedCreate  replication-controller  Error creating: pods "test-rc-7h684" is forbidden:
  Post "https://image-webhook.example.com:443/?timeout=30s": dial tcp: lookup
  image-webhook.example.com ... no such host
```

So: **`kubectl apply` succeeding tells you nothing.** The denial shows up in `kubectl describe rc` events
and in `CURRENT: 0`. To see the message directly, create a bare Pod instead:

```bash
kubectl run ipw-test --image=nginx
# Error from server (Forbidden): pods "ipw-test" is forbidden:
#   Post "https://image-webhook.example.com:443/?timeout=30s": dial tcp: ... no such host
```

That `Forbidden` + webhook URL in the message is proof that the plugin is loaded, the config file parsed,
and `defaultAllow: false` is in effect.

> 💡 With `defaultAllow: false` and a webhook that isn't reachable, **no Pod can be created anywhere** in
> the cluster. That is the correct end state for this task, but expect everything else to stall. If you
> need a working cluster afterwards, remove `ImagePolicyWebhook` from `--enable-admission-plugins` and
> delete the `--admission-control-config-file` flag.

`journalctl -u kubelet -f` shows the **kubelet's** view (static pod restarts), not API server admission
decisions. For those use `crictl logs` as shown above.

### ✅ Validated on a live cluster

| Step | Result |
|---|---|
| `kind: ImagePolicyWebhook` as the admission config file | ❌ API server refuses to start (`no kind ... is registered`) |
| `kind: AdmissionConfiguration` + `plugins[].configuration.imagePolicy` | ✅ `kubectl get --raw /healthz` → `ok` |
| hostPath mount for `/etc/kubernetes/imagepolicy` omitted | ❌ crash loop, file not found inside the container |
| `defaultAllow: false` + unreachable webhook | ✅ Pod creation `Forbidden`; RC created but `CURRENT: 0` |
