
## Question 15

> You have a Pod with **3 containers** using different Docker images.
>
> 1. Scan all three images to find which image contains a specific package libcrypto3 and version 3.5.4-r0.
> 2. Generate an **SBOM report in SPDX format** for that image using `bom` and save it to the location specified in the exam.
> 3. Generate a **CycloneDX report** for the same image using `trivy` and save it to the location specified in the exam.

---

### Solution:

# ✅ **Step 1 — Identify the Pod and its container images**

```bash
# Get the pod name
kubectl get pods -A

# Inspect the pod to see the container images
kubectl describe pod <pod-name> -n <namespace> | grep -i image
```

Or:

```bash
kubectl get pod <pod-name> -n <namespace> -o jsonpath='{.spec.containers[*].image}'
```

Note the three container images (e.g., `alpine:3.20`, `alpine:3.21`, `alpine:3.22`).

---

# ✅ **Step 2 — Pull all images (if not already pulled)**

```bash
docker pull <image1>
docker pull <image2>
docker pull <image3>
```

# ✅ **Step 3 — Scan each container for the specified package**

The exam will provide a package name and version to search for (e.g., `libcrypto3 version 3.5.4-r0`).

**Method 1: Using kubectl exec (Recommended for Alpine-based containers)**

Since the containers are already running in the pod, you can directly check installed packages:

```bash
# Get container names from the pod
kubectl get pod <pod-name> -n <namespace> -o jsonpath='{.spec.containers[*].name}'

# or 

kubectl get po  <pod-name> -o yaml | grep -i image: -A3 -B2

# Check packages in each container
kubectl exec <pod-name> -n <namespace> -c <container1-name> --  apk info -v -i -e -a | grep -i "libcrypto3"
kubectl exec <pod-name> -n <namespace> -c <container2-name> --  apk info -v -i -e -a | grep -i "libcrypto3"
kubectl exec <pod-name> -n <namespace> -c <container3-name> --  apk info -v -i -e -a | grep -i "libcrypto3"
```

To get package version details:

```bash
kubectl exec <pod-name> -n <namespace> -c <container-name> -- apk info -v -i -e -a | grep -i "libcrypto3"
```


Example output when found — verified across three real Alpine tags:

```
$ docker run --rm alpine:3.20 apk info -v -i -e -a | grep '^libcrypto3'
libcrypto3-3.3.7-r0
$ docker run --rm alpine:3.21 apk info -v -i -e -a | grep '^libcrypto3'
libcrypto3-3.3.7-r1
$ docker run --rm alpine:3.22 apk info -v -i -e -a | grep '^libcrypto3'
libcrypto3-3.5.8-r0
```

The format is `<name>-<version>-r<rev>`, so matching the task's `libcrypto3` **and** `3.5.4-r0` means
matching the whole string `libcrypto3-3.5.4-r0`. Note how close `3.3.7-r0` and `3.3.7-r1` are between
tags — read the revision suffix carefully; that's where this task is won or lost.

> 💡 If a container has no shell / `apk` (distroless, scratch), fall back to `trivy`, which reads the
> image rather than executing inside it:
>
> ```bash
> trivy image --scanners vuln --list-all-pkgs --format json <image> | grep -i libcrypto3
> # or simply
> trivy image <image> | grep -i libcrypto3
> ```

# ✅ **Step 5 — Generate SBOM report using bom**

The exam will specify the output location and format. Use `bom generate` with the format specified.

```bash
bom generate --format json --image <image-name> -o <output-path>

# Example:
bom generate --format json --image alpine:3.22 -o /opt/course/3/spdx.json
```

> ### ⛔ `bom` only accepts three format values — and `spdx-json` is **not** one of them
>
> Verified with `bom` v0.8.0:
>
> ```
> $ bom generate --format spdx-json --image alpine:3.18 -o /tmp/x.json
> level=fatal msg="validating command line options: unknown format provided,
>   must be one of [tag-value, json, spdx3-json]: spdx-json"
> ```
>
> ```
> --format string   format of the document (supports json, tag-value, and spdx3-json,
>                   which is experimental) (default "json")
> ```
>
> **`bom` always emits SPDX** — `--format` only picks the *encoding*:
>
> | `--format` | Output |
> |---|---|
> | `json` (default) | SPDX **2.3** in JSON  ← this is what "SBOM in SPDX format" means |
> | `tag-value` | SPDX 2.3 in classic `.spdx` tag-value text |
> | `spdx3-json` | SPDX 3.0.1 JSON-LD (experimental) |
>
> So the old "For SPDX format" and "For JSON format" blocks were the **same command** labelled two ways.
> There is one command; `--format json` is both.
>
> Confirmed output:
>
> ```
> $ head -5 /opt/course/3/spdx.json
> {
>   "SPDXID": "SPDXRef-DOCUMENT",
>   "name": "SBOM-SPDX-66cceae5-...",
>   "spdxVersion": "SPDX-2.3",
> ```

# ✅ **Step 6 — Generate CycloneDX report using trivy**

Use `trivy image` with CycloneDX format. The exam will specify the output location (e.g., `/opt/course/3/result.cdx`).

```bash
trivy image --format cyclonedx --output <output-path> <image-name>

# Example:
trivy image --format cyclonedx --output /opt/course/3/result.cdx alpine:3.18
```

# 📌 **Command Reference**

**kubectl exec (for finding packages in running containers):**
```bash
# List all packages in a container
kubectl exec <pod-name> -n <namespace> -c <container-name> -- apk info

# Search for a specific package
kubectl exec <pod-name> -n <namespace> -c <container-name> -- apk info | grep -i <package-name>

# Get detailed info about a package
kubectl exec <pod-name> -n <namespace> -c <container-name> -- apk info <package-name>
```

**bom commands (for generating SBOM reports):**
```bash
# SPDX 2.3 as JSON  (this IS "SPDX format"; --format json is the default)
bom generate --format json --image <image-name> -o <output-path>

# SPDX 2.3 as tag-value text
bom generate --format tag-value --image <image-name> -o <output-path>

# NOTE: `--format spdx-json` does NOT exist and exits fatal.
# Valid values: tag-value | json | spdx3-json
```

Useful flag aliases: `-i` = `--image`, `-o` = `--output`. Omit `-o` and it writes to stdout.

**trivy commands:**
```bash
# Scan image for packages/vulnerabilities
trivy image <image-name>

# Generate CycloneDX format
trivy image --format cyclonedx --output <output-path> <image-name>
```

```
$ trivy image --format cyclonedx --output out/result.cdx alpine:3.22
$ head -4 out/result.cdx

  "$schema": "http://cyclonedx.org/schema/bom-1.7.schema.json",
  "bomFormat": "CycloneDX",                    # CycloneDX ✅
  "specVersion": "1.7",
```

### 🔍 Before you finish — check the files are real

Both tools exit 0 and write a file even when the scan found little, so confirm content, not just existence:

```bash
ls -l <output-path>                             # non-trivial size
grep -o '"spdxVersion":"[^"]*"' <spdx-file>     # SPDX-2.3
grep -o '"bomFormat":"[^"]*"'   <cdx-file>      # CycloneDX
```

Write to the **exact path and filename** the task gives (e.g. `/opt/course/3/result.cdx` — note the
extension; `bom`/`trivy` won't add or correct one), and `mkdir -p` the directory first if it doesn't exist.
